# Tauri desktop workflow

The app opens on **Recorder**. Choose system output and microphone, then use Record, Pause/Resume, and Stop. The state and timer are labeled; capture begins only after Record. Saved recordings appear in **Meetings**, where users can import WAV, MP3, M4A, or FLAC, play audio through the meeting-bound waveform, start local transcription, and review timestamped text. **Models** lists recommended Whisper models and downloads one only after a click. **Settings** manages optional provider profiles, dark/light theme, and interface language. The interface starts in English; use the header switch or Settings to select Vietnamese, and the choice is saved locally. Transcription and minutes remain Vietnamese by default, independently of the interface language. Saved meeting names, transcripts, and minutes are not translated by the switch. If the Python sidecar stops, **Restart backend** reopens saved local state; incomplete recordings appear under **Recover recordings**.

Recording, importing, selecting an installed model, transcription, playback, transcript editing, and **Create offline draft** require no API key. A network connection is needed only for an explicit model download or a separately confirmed provider request. New and legacy M1 meetings are treated as Internal/Restricted.

To make minutes, review and save the transcript, then use **Offline draft** in Meetings. The result is an unverified extractive draft with source timestamps. Select a citation to open its transcript run or seek source audio. Edit the draft and save a new version, then approve a version after checking it. Regeneration never overwrites an approved version. **Edit offline template** changes Vietnamese headings, guidance, and topic count for future drafts.

For optional provider minutes, create a profile in Settings. In Meetings, manually change the meeting to **Cloud Allowed**, select transcript rows, mark each selected row **Reviewed**, choose or edit the prompt template, and set a token limit. **Preview provider payload** shows the hostname and complete outgoing request body. **Cancel** sends nothing; **Confirm and send** authorizes that one send. A retry requires a new preview and confirmation. The generated result remains unverified and may contain mistakes; follow its source citations before approving. Provider errors leave your audio, transcript, and previous minutes intact. See [privacy and data flow](privacy-minutes.md) and [provider setup](provider-setup.md).

To take a document out of fahmm, save any transcript or minutes edits first. Select the transcript run and click **Export TXT** for its corrected working text. Select the minutes version and click **Export MD** for that version's Markdown, or **Copy Markdown** to put the same saved text on the system clipboard. A selected unverified version remains labeled unverified. The OS save dialog chooses a destination outside fahmm's managed meeting/model folders; replacing an existing file requires confirmation. Cancel creates no output. Shared or cloud-synced locations and the clipboard may be accessible to other applications. See the [export format guide](export.md).

To remove a meeting, select it in **Meetings**, click its delete icon, read the named confirmation, and confirm. Cancel leaves the meeting untouched. The audio player closes when the meeting disappears. Wait for recording, transcription, import, or minutes generation to finish if deletion is refused for active work. The selected meeting disappears only after deletion succeeds. Other meetings, installed models, provider profiles, and the original file used for an import remain. Exported files, clipboard copies, and system backups remain too; ordinary deletion does not securely erase storage.

If Windows reports that deletion could not finish, the meeting may already have disappeared from the list while data remains in an incomplete deletion. In **Meetings → Storage cleanup**, click **Retry cleanup** after releasing any file lock. An interrupted import may appear as an abandoned import; click **Clean import**, then confirm. This removes only fahmm's unfinished import copy, leaving the source file where it was. See [storage and recovery](storage-migration.md).

Development launch: `uv sync` at the repository root, then `npm ci` and `npm run tauri dev` under `desktop/`. Data stays under `%LOCALAPPDATA%\fahmm`. Close Tauri before using the earlier Qt ZIP from `release/` for rollback; both apps use the same meeting library and instance lock. Check its SHA-256 file, extract it, and reopen a saved meeting in **Meetings**. The development-host rollback check is `uv run --locked --extra legacy-qt python scripts/verify_qt_rollback.py` from the repository root. Windows distribution checks remain part of M4.
