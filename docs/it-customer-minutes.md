# IT customer meeting minutes data

New customer-facing minutes versions use `domain_schema_version: 1` in `minutes/<version-id>/content.json`. The [example payload](../tests/fixtures/domain_minutes_example.json) is saved and re-read by `tests/test_minutes_domain.py`. Replace its placeholder `run_id` with the selected transcript run before saving. The meeting type is `general`, `requirement_gathering`, `technical_discussion`, `project_status`, `issue_incident`, or `uat_feedback`. Common and relevant type-specific sections use the same claim format; empty optional sections may be omitted.

Each metadata field has a value, provenance (`unknown`, `user_provided`, or `source_supported`), and citations. The actual `meeting_datetime` starts as unknown. The meeting's `created_at` is the time fahmm recorded or imported it; it is never substituted for the actual meeting time. Participants are plain names or roles supplied or reviewed by a person, not identified speakers.

Each claim has a stable `item_id`, text, origin, review status, and zero or more source references. Generated claims require a citation. A source contains the selected transcript run ID, exact segment ID and timestamps, and an `excerpt` copied from that run's working text when the version is saved. The saved excerpt stays in the local minutes file even if the working transcript is edited later. fahmm compares it with current text and requires renewed review before approving a changed source. A citation proves where a claim came from; it does not prove the claim is true. User-provided claims without citations remain marked as such.

The existing manifest records the run, origin, parent version, and whole-document review state. Editing or regenerating creates a new atomic version and does not rewrite an approved predecessor or an ASR artifact. Each generated claim must be confirmed or rejected before internal document approval. Approval is not customer sign-off. Rejected claims are retained for audit but omitted from the finished document.

Legacy generic minutes files keep their old shape and remain readable, selectable, and approvable. Rolling back to an older app does not delete new domain files, but that app may omit domain-only sections when rendering. Return to a version supporting `domain_schema_version: 1` to review them. Do not manually down-migrate or rewrite saved versions. Saved excerpts are sensitive local meeting data and follow the same meeting deletion and backup limits described in [storage migration](storage-migration.md); an export or external backup remains outside fahmm's deletion scope.
