# Minutes privacy and provider data flow

Each new meeting starts as **Internal/Restricted**. Missing or invalid classification is treated the same way. In this mode, recording, local transcription, transcript review, and the source-linked extractive minutes draft stay on the device. A provider request carrying meeting content is rejected by the service before network transport, including when invoked outside the UI. A local failure never triggers a cloud fallback or a provider connectivity probe.

For a **Cloud permitted** meeting, select and review the exact transcript segments to share. The app builds a snapshot of those edited segments, the generation prompt, model, and token limit. The disclosure preview shows the destination hostname, data types, warning, and exact request body. Closing or canceling the preview sends nothing. Confirming creates a single-use authorization bound to that snapshot and provider profile. Immediately before transport, the app checks the meeting mode, active transcript, selected text, profile, and payload again. A retry or regeneration needs a fresh preview and confirmation. Audio, unrelated transcript runs, other meetings, local paths, stored minutes, and API keys are not put in the request body.

The OpenAI-compatible provider is optional. Remote Base URLs require HTTPS with normal TLS verification. Plain HTTP is allowed only for explicit loopback localhost addresses. Content-bearing requests do not follow redirects. A loopback endpoint still uses Cloud permitted mode and the same disclosure gate. API keys are retrieved from Windows Credential Manager only for an authorized send; profile JSON and meeting folders contain no plaintext key. Provider errors shown to the user are sanitized, and failed requests preserve local data.

Provider output is untrusted. Valid source IDs are linked back to the selected transcript timestamps; invalid IDs are discarded, and affected claims remain flagged for review. Missing owners, deadlines, attendees, or decisions show `Chưa rõ`. A valid citation does not prove the statement is true, so every provider version remains unverified until a person reviews and approves it. The offline draft is also unverified and extractive rather than a full semantic summary.

Model downloads are a separate explicit action and contain no meeting audio or transcript. fahmm does not add telemetry, automatic content sync, or automatic meeting-content uploads. These controls describe data flows in fahmm; they do not assess an external provider's retention policy.

The Restricted and Cloud permitted service paths are exercised by `uv run pytest -q tests/test_cloud_minutes.py tests/test_provider_transport.py tests/test_provider_minutes.py`. The tests include cancelled and stale confirmations, blocked socket attempts, a loopback provider, and retryable errors.
